# Continue the chosen design

## Read the existing authority

Use the person's explicit choices, then the project's applicable design rules,
tokens, components, and coherent neighboring screens. An existing look is
evidence, not permission to override an explicit redesign. Separate product
facts, accepted choices, AI proposals, assumptions, and observed behavior.

When a pattern drifts, identify the cause: a local defect, an unused existing
component, a missing reusable token, or a conceptual change. Fix it at that
level. Do not generate a three-tier token system for a one-off value or migrate
the whole project for one screen.

## Record only what another use needs

For same-session local work, the conversation and resulting files may be enough.
When another screen, session, or worker must use the decisions, update the
established project design record. Create a small ordinary project document
only when no suitable record exists. Do not impose a new filename, schema,
sidecar, preference database, or second source of token values.

Keep the selected direction, reasons and trade-offs, important patterns and
states, reusable design rules, and intentional local exceptions. Link actual
tokens and components rather than copying their values into a competing source.
Record material reference influences and what was not observed. Retain rejected
directions only when their reason prevents repeated mistakes; do not accumulate
every experiment as a permanent rule.

Don't turn one task's taste into a global preference. A person can want a dense
admin tool and an expressive portfolio. Distinguish project-wide choices from
surface-specific ones, and don't infer approval from silence or a tool failure.

## Hand off a result someone can use

Include exact paths, the selected option and decision basis, important content
and behavior constraints, responsive/state decisions, reusable components or
tokens, and verification scope. Preserve runnable source, needed assets, and
start/view instructions when the result depends on a local server. Identify
simulated interactions and any material implementation gap.

Read the current target before implementing from an older design record. Resolve
new conflicts rather than blindly replaying stale values. Use existing implementation
authority and continue without a new approval for routine mechanics. Escalate
only new material choices beyond that authority.

## Own temporary work

Track created files and process identities when creating them. Keep accepted
artifacts and evidence for the promised handoff. Remove only known unneeded
exploration within the authorized scope; preserve uncertain or user-owned files.
State what temporary preview remains and how to stop or resume it when relevant.

Align owns its agreement artifact and its revision rules. Return Design's
evidence through the public handoff in SKILL.md; do not write an independent
competing agreement or treat a temporary prototype URL as durable content.
